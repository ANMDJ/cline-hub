它解决什么

不是又一个「AI 聊天壳」，而是给长时间运行的 agent 补上「离开桌面之后」的那一段。

01

离开就失联

Cline 的任务动辄几十分钟。现在你在外面也能看到「跑完了 / 报错了 / 被中断了」，以及最后的输出。

02

结果散落各处

会话记录存在本机 SQLite，跨机器、跨设备没法翻。Hub 用 Postgres 统一收口，支持全文搜索与游标分页。

03

回不了指令

看完结果想让它接着干，不必回到电脑前：手机上写一句，Windows 侧按模板执行，结果原路回写。

特性

全部围绕一件事：让「本机 agent」变成「可远程观测、可远程驱动」的常驻服务。

会话回溯

按 updated_at 水位线增量读取 sessions.db + messages.json，只抽结果文本与命令， 重复上报走 upsert，断网时先进 outbox 队列，恢复后补传。

实时下行

一条 SSE 长连接 GET /api/v1/events，新会话、新命令即时到达；命令运行期间 App 挂一条静音前台服务保活， 锁屏也能立刻收到结果；断线自动退化为轮询，不丢事件。

远程命令与取消

App 下发 → Hub 排队 → 采集器用 FOR UPDATE SKIP LOCKED 领取 → 本地执行 → 回写 running / done / failed / cancelled；排队中可撤回，执行中按 commandId 杀进程树。

模板化执行 · 并发池

命令不是一个裸 shell：由 template 决定怎么跑（{prompt} 直接当脚本，或 cline --yolo "{prompt}"），脚本先落临时文件，绕开引号转义地狱； commands.concurrency 让不同工作目录并行，同一目录强制串行。

多设备

GET /api/v1/devices 列出每台电脑的在线状态、会话数与待执行 / 执行中命令； device token 只能读自己（跨设备 403 device_mismatch）， App 里按设备筛选、也能设为默认。

结构化输出

给 cline 固定加 --json，增量解析终稿、失败原因与用量；会话正文在 App 里按 Markdown 渲染，命令输出仍保持终端原文。

零框架后端

裸 node:http + pg，唯一依赖就是驱动；8 个 SQL 迁移幂等建表， 单文件 Docker 镜像，常驻内存个位数 MB。

可自证健康

自带 smoke 脚本，22 项检查覆盖鉴权、分页、搜索、命令闭环、设备列表、SSE， 任何一项红就 exit 1，可以直接当部署闸门。

架构

三段式，没有消息队列、没有 K8s，出问题时一眼能看出卡在哪一段。

Windows

采集器 · 执行器

  • Cline Hooks（结束 / 失败 / 中断）
  • 增量读 sessions.db + messages.json
  • 127.0.0.1:3210 本地 hook 服务
  • 按模板执行、按 pid 登记与对账
HTTPS · token

Hub

Ubuntu · Caddy · Docker

  • REST + SSE（node:http）
  • Postgres：devices / sessions / messages / hooks / commands
  • 设备隔离 + SHA-256 token + 每 IP 限流
  • 只监听 127.0.0.1，Caddy 反代
SSE · 轮询

Android

Flutter 客户端

  • 会话 / 项目聚合 / 逐条消息，Markdown 渲染
  • 下发命令、排队撤回、完成通知
  • 设备列表与筛选、执行中实时耗时
  • SSE 实时刷新（断线退化轮询）
  1. 实时：Cline hook → 本地脚本 → 推送（手机立刻收到）+ /hook（进库）
  2. 回溯：采集器按水位线扫 sessions.db → 抽结果与命令 → 上报 Hub
  3. 下发：App → POST /api/v1/commands → 采集器领取 → 本地执行 → PATCH 回写
  4. 推送：App 保持 GET /api/v1/events，断线退化为轮询

五分钟自建

三个部件都是普通 Node 进程 / 静态文件，没有魔法。下面以 Linux 服务端 + Windows 本机为例。

1服务端：起 Hub

git clone https://github.com/ANMDJ/cline-hub.git && cd cline-hub/server
cp .env.example .env        # 填库地址、管理令牌
docker compose build
docker compose run --rm hub node src/migrate.js
docker compose up -d
node scripts/create-device.mjs --id localone --name "我的 Windows"  # 打印一次性 token
node scripts/create-device.mjs --id phone --kind app --name "我的手机"

2反向代理：Caddy 兜住 TLS 与 SSE

hub.example.com {
    encode zstd gzip
    @events path /api/v1/events*
    reverse_proxy @events 127.0.0.1:3100 {
        flush_interval -1      # SSE 必须实时下发
    }
    reverse_proxy 127.0.0.1:3100
}

3Windows：装 hook + 起采集器

# hook 放进 Cline 的全局 Hooks 目录
copy hooks\*.ps1 "%USERPROFILE%\Documents\Cline\Hooks\"

# 采集器（开机自启见 deploy/windows/ClineBridge.vbs）
cd bridge
node src/index.js
curl http://127.0.0.1:3210/health

4验收：跑冒烟

HUB_SMOKE_BASE=https://hub.example.com node server/scripts/smoke.mjs \
  --token-device <device-token> --token-app <app-token>
# 22/22 checks passed

手机端（Flutter App）在 app/ 下：可以直接装 1.1.7 的 APK，也可以自己 flutter build apk --release； Hub 地址与 token 走 App 内的向导，不写死在代码里。

安全边界

「远程执行命令」是这套东西最危险的部分，所以默认全关，且每一步都要留痕。

默认关闭

不配就不执行

commands.enabled=false 时，命令会一直停在 pending，采集器看都不看。 要开就得显式改配置，并选好模板。

白名单

模式要过筛

allowModes 默认只放行 plan / act，yolo 不在名单里； 越权请求直接 failed 并写明原因。

可回收

能停得下来

超时按进程树强杀（taskkill /t /f），状态机只走 pending → delivered → running → done / failed / cancelled，每一步带时间戳。

鉴权

token 只存哈希

库表里只有 SHA-256 摘要，比对用 timingSafeEqual；设备与 App 是两类角色， 拿 App 的 token 打设备接口会 403。

限流

每 IP 令牌桶

默认 120 突发 / 5 rps 恢复，超限 429 + retry-after；可选 CIDR 白名单， 本机回环永远放行，不至于把自己锁在外面。

网络

只信自己的反代

Hub 只监听 127.0.0.1；只有直连方是回环时才采信 X-Forwarded-For， 避免伪造来源绕过限流。

常见问题

为什么不直接用 Cline 自带的历史记录？

自带的记录绑在这台机器上：换个设备看不到，任务跑完人不在也没提示，更没法从外面把下一条指令递进去。

APK 在哪下载？跟仓库版本怎么对？

当前是 1.1.7：直接下 APK（约 53 MB）。 也可以自己 flutter build apk --release。App 内「检查更新」读的是 GET /api/v1/app/latest，指向同一个文件；版本与改动见 CHANGELOG。

必须有自己的服务器吗？

是。Hub 需要一台能常开的 Linux（1 核 1G 足够）和一个 Postgres。不想自己装数据库也行， 用任何托管 Postgres，改 HUB_DATABASE_URL 即可。

没有域名、或者域名还没备案能用吗？

能。Hub 只监听本地回环，对外那层可以随便换：域名、纯 IP、加随机路径前缀、 甚至套 Cloudflare Tunnel。客户端只是改 baseUrl，接口和鉴权完全不变 —— 这套东西就是被「域名不可用」逼出来验证过的。

远程执行命令会不会很危险？

会，所以默认关闭。开启后仍然有三道闸：模式白名单（yolo 默认不放行）、 模板固定可执行形态、超时强杀进程树；每条命令的完整生命周期都带时间戳落库，可事后复盘。

数据会被上传到第三方吗？

不会。会话、命令、token 摘要全部在自己的 Postgres 里；仓库里不出现任何真实口令， .env 与 bridge/config.json 都在 gitignore 里。

Windows 端为什么不注册成系统服务？

为了不要求管理员权限。现在用「启动文件夹 + VBS 隐藏窗口」自启，普通用户即可； 想换成计划任务，一条 schtasks 命令的事。

自己跑一份

代码、迁移脚本、Caddy 配置、冒烟用例都在同一个仓库里，没有隐藏的私有依赖。
